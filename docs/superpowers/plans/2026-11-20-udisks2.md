# udisks2 on the desktop variants Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship udisks2 (udisksd, udisksctl, its D-Bus and polkit files) on sway, i3, COSMIC and niri, so a user in an active local session can mount a removable disk without root, and the Welcome Backup page can list and mount USB disks.

**Architecture:** udisks2 and its required libraries (libblockdev with the smallest plugin set udisks2 accepts, libbytesize) are built from source in new Dockerfile stages, following the stages of PR #120 (libgudev, upower). They are copied into `desktop-default`, so the four variants get them. udisksd is D-Bus activated and also enabled like upower. A polkit rule lets an active local session mount removable filesystems.

**Tech Stack:** Dockerfile multi-stage builds on `ghcr.io/kairos-io/hadron-toolchain`, meson/autotools, D-Bus, polkit, udev.

**Spec:** `docs/superpowers/specs/2026-11-20-isotope-welcome-design.md`, section "Disks", and "Order of work" step 4.

## Global Constraints

- Everything is built from source in the Dockerfile; each new source has a `# renovate:` comment, a version ARG, and the existing curl flags (`-f --retry 5 --retry-delay 3 --retry-all-errors -L`).
- Installed on the four desktop variants (sway, i3, cosmic, niri) through `desktop-default`. Not on the server (no `desktop-default`). The agent image: removed by `Dockerfile.agent` (an AI-driven appliance must not mount disks a person plugs in); say so in the PR.
- Daemons live under `--libexecdir=lib` like polkit, flatpak and upower (`/usr/lib/udisks2/udisksd`).
- Units that say `WantedBy=graphical.target` are linked into `multi-user.target.wants`, as bluetooth and upower are (Kairos never reaches graphical.target).
- No Python at runtime (the base image has none).
- libgudev comes from PR #120's `libgudev` stage. Branch from `ci-forks/fix/upower-battery` until #120 merges, then rebase onto `origin/main` before opening the PR (or open it as stacked on #120 and say so).
- AGENTS.md feature table gains a "Removable disks" row in the same PR.

## Review Focus

1. A USB stick formatted exFAT or NTFS (most sticks people own): udisks must mount it. The kernel has `CONFIG_EXFAT_FS=m` and `CONFIG_NTFS3_FS=m`; udisks2 maps `ntfs` to the `ntfs3` driver only if configured to; the test mounts an exFAT image and an NTFS image.
2. A non-admin user in an active session can mount a removable disk, but a session over SSH (inactive/remote) cannot: the polkit rule must check `subject.active && subject.local`.
3. A system disk (the install disk's own partitions, `COS_*` labels) must not be offered or mounted as removable: udisks' `HintSystem`/`HintIgnore` must be true for them. A udev rule sets `UDISKS_IGNORE=1` for `COS_*` and `*_LUKS` labels.
4. udisksd must start on boot of an installed image and on the live ISO without delaying the login screen: D-Bus activation, no `After=` on network.
5. The mount point: `/run/media/<user>/<label>` with the user as owner (udisks default), so the Backup page can write into it; vfat/exfat mounted with `uid=` of the user.

### Task 1: Build libbytesize, libblockdev and udisks2

**Files:**
- Modify: `Dockerfile` (new stages after the `upower` stage from #120; the `desktop-default` COPY block)
- Modify: `Dockerfile.agent` (remove udisks2's files)

**Interfaces:**
- Consumes: the `libgudev` stage (#120), the toolchain's glib, polkit, libmount (util-linux), kmod, json-glib, gmp, mpfr, pcre2, libucontext (see #120: the toolchain's libsystemd needs it at link time).
- Produces: stages `libbytesize`, `libblockdev`, `udisks2`, each installing into its own `/out`-style root that `desktop-default` copies (same shape as #120's stages).

- [ ] **Step 1: Pick the versions and the plugin set**

Latest stable udisks2 2.x and libblockdev 3.x that build against the toolchain. Read udisks2's `meson.build`/`configure.ac` for the libblockdev plugins it hard-requires and enable exactly those (expect: `fs`, `loop`, `mdraid`, `part`, `swap`; plus `crypto` and `nvme` if required). Disable the optional modules (`--disable-lvm2`, `--disable-btrfs`, `--disable-iscsi`, `--disable-lsm`, `--disable-zram`, `--disable-smart`) and gtk-doc, man pages and introspection. If a required plugin needs a library the toolchain lacks (libcryptsetup for `crypto`, libnvme for `nvme`), add a stage for that library the same way, and note it in the PR.

- [ ] **Step 2: Write the stages and build them**

Run: `docker buildx build --target udisks2 --build-arg HADRON_VERSION=<the Dockerfile's default> -f Dockerfile .`
Expected: the stage builds, and its last RUN line prints `udisksctl --version` from the staged root (add `"$root"/usr/bin/udisksctl --version` with `LD_LIBRARY_PATH` set to the staged lib dirs, as the cage stage runs `cage -v`).

- [ ] **Step 3: Copy into `desktop-default`, remove in `Dockerfile.agent`**

Copy the three stages' roots in `desktop-default` next to upower's. In `Dockerfile.agent`, remove `/usr/bin/udisksctl`, `/usr/lib/udisks2`, udisks' D-Bus service and policy files, its polkit action, its units and udev rules (the exact list from the staged root).

- [ ] **Step 4: Commit**

```bash
git add Dockerfile Dockerfile.agent
git commit -s -m "feat(disks): build udisks2 and libblockdev for the desktops"
```

### Task 2: Enable, polkit rule and ignore the system disk

**Files:**
- Create: `rootfs/usr/share/polkit-1/rules.d/50-isotope-udisks.rules`
- Create: `rootfs/usr/lib/udev/rules.d/90-isotope-udisks-ignore.rules`
- Modify: `Dockerfile` (the `multi-user.target.wants` link, next to upower's)
- Modify: `test/boot-ux/check-boot-units.sh` (the checks #120 added for upower are the model)
- Modify: `AGENTS.md` (feature table row)

**Interfaces:**
- Produces: `org.freedesktop.UDisks2` on the system bus; mounts at `/run/media/<user>/<label>`.

- [ ] **Step 1: Add the failing image checks to `check-boot-units.sh`**

For every image but the server and the agent: `/usr/lib/udisks2/udisksd` exists and its libraries resolve (`ldd` with no "not found"); `udisks2.service` exists and is linked in `multi-user.target.wants`; `/usr/share/dbus-1/system-services/org.freedesktop.UDisks2.service` and `/usr/share/dbus-1/system.d/org.freedesktop.UDisks2.conf` exist; `/usr/share/polkit-1/actions/org.freedesktop.UDisks2.policy` and `50-isotope-udisks.rules` exist; `90-isotope-udisks-ignore.rules` exists. For the agent image: `udisksd` is absent.

- [ ] **Step 2: Run the checks against the current image, see them fail**

Run: the way #120 ran `check-boot-units.sh` against a throwaway image (build `--target desktop-default` or copy the staged files onto `ghcr.io/kairos-io/hadron:<HADRON_VERSION>`).
Expected: FAIL on the udisks2 checks.

- [ ] **Step 3: Write the polkit rule**

`50-isotope-udisks.rules`: for actions `org.freedesktop.udisks2.filesystem-mount`, `org.freedesktop.udisks2.filesystem-unmount-others` (only for a filesystem the same user mounted is already allowed by default; keep that), `org.freedesktop.udisks2.eject-media`, `org.freedesktop.udisks2.power-off-drive`: return `polkit.Result.YES` when `subject.local && subject.active`; otherwise fall through. Mounting a system disk (`filesystem-mount-system`) is not granted.

- [ ] **Step 4: Write the udev ignore rule**

`90-isotope-udisks-ignore.rules`: `ENV{ID_FS_LABEL}=="COS_*", ENV{UDISKS_IGNORE}="1"` and the same for `ENV{ID_FS_LABEL}=="*_LUKS"` and `ENV{ID_FS_TYPE}=="crypto_LUKS"` on non-removable devices, so the Kairos partitions never show as mountable.

- [ ] **Step 5: Enable the unit, run the checks, see them pass**

Link `udisks2.service` into `multi-user.target.wants`. Re-run Step 2's command.
Expected: PASS.

- [ ] **Step 6: Mount test with real filesystems (Review Focus 1, 3, 5)**

In a privileged container or a VM booted from the built image, as a user in an active session (or with the polkit rule exercised through `pkcheck --process`): create loop-backed exFAT, NTFS and vfat images (`mkfs` tools may come from a throwaway container; the image needs only the kernel drivers), `udisksctl loop-setup -f img`, `udisksctl mount -b /dev/loopNp1`.
Expected: each mounts under `/run/media/<user>/<label>`, owned by the user; a `COS_PERSISTENT`-labeled image is not listed by `udisksctl status`/`dump` as mountable (HintIgnore true).
If a full VM is not possible here, run what is possible in a privileged container and leave the VM check to the laptop, saying so in the PR.

"Removable disks": udisks2 (libblockdev, plugin list) on the four variants, `50-isotope-udisks.rules` lets an active local session mount removable media, `90-isotope-udisks-ignore.rules` hides the Kairos partitions, mounts under `/run/media/<user>`; not on server; agent removes it.
